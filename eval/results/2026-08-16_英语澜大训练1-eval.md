## 迭代过程（7 次运行，暴露并修复 10 个 bug）

| 运行 | 错题 P / R / F1 | 发现的问题 |
|------|------|------|
| Run 1 | 86.4% / 82.6% / 84.4% | ① VL分类 data-URL 当文件路径 → ENAMETOOLONG；② merged路径所有题塞进第1页（跨页红笔污染，成绩虚高）；③ merged 不返回 handwritten_regions → 交叉验证失效 |
| Run 2 | — (4 错) | ④ LLM 未回显 itemIndices → bbox 全零 → 判错崩塌 |
| Run 3 | 77.3% / 73.9% / 75.6% | ⑤ 文本匹配恢复 bbox 后，多题共享同一 bbox → 贪心质心分配饿死后题 |
| Run 4 | 80.8% / 91.3% / 85.7% | 共享 bbox 垂直均分后收敛（当时代码基线） |
| Run 5 | 崩塌 (11题/0错) | **⑥ http→https: zhipuVLRequest/Kimi用 http 模块调 https 端点 → 301 → VL 从未成功过（生产同样！）**；⑦ DeepSeek 慢导致 merged 超时；⑧ 低覆盖阈值把解析成功的稀疏页（P3 8块/2题、P4 14块/4题）强制丢进 VL 回退然后失败 |

| Run 7 | **83.3% / 87.0% / 85.1%** | 精确题号匹配修复 |

### 修复清单

1. **scanner-v3.mjs** `imgToBase64()`: data URL 直通（`/preprocess` 返回的红笔图是 data URL，此前被当文件路径打开 — **该 bug 在生产同样存在，VL 红笔分类一直是静默失败的**）
2. **scanner-v3.mjs** merged 路径: 按 LLM pageIndex 把题目分发回各自页（此前全塞第 1 页）
3. **preprocess-server.py** `/textin/ocr-merged`: 返回带 pageIndex 的 `handwritten_regions`（恢复 v4.5 TextIn 交叉验证）
4. **llm_parser.py** `_recover_missing_bboxes()`: LLM 漏回显 itemIndices 时，用题干/选项文本归一化匹配 OCR item 重建 bbox
5. **llm_parser.py** `_split_shared_bboxes()`: 共享 bbox 垂直均分 + 相邻包含收缩（解决连续小题贪心饿死）
6. **scanner-v3.mjs** Kimi fallback 端点: `api.moonshot.cn` → `dashscope.aliyuncs.com/compatible-mode`（KIMI_API_KEY 实为 DashScope key）
7. **★ scanner-v3.mjs http→https**: `zhipuVLRequest`/Kimi 分类用 `http` 模块（80端口）调 https 端点 → 永远收到 301 重定向页。**智谱 VL 在生产从未成功过**（此前所有 "<html>" 错误都是它，与 key 无关）
8. **scanner-v3.mjs** 低覆盖阈值: 仅当页 OCR 块少 **且解析出 0 题** 时才强制 VL 回退（原逻辑把解析成功的稀疏页丢掉）
9. **scanner-v3.mjs** VL标记→题目匹配: `includes` 子串改为整数精确提取（Q1 不再偷走 "题号11旁边"）
10. **zhipuVLRequest**: 加 `thinking: {type:'disabled'}`（分类/OCR 不需要推理链，更快更省）

## 残留误差分析（Run 7）

**FP（4 个，全部是"红笔在旁边但题没错"）**: Q6/Q10/Q24/Q66。该教师批改风格是**每题旁都写红笔字母**（答案键式），VL 把这些字母分类为 correct_answer（判错依据）——但对的题旁也有字母。**几何+形态学已到天花板**，需要语义级判定（读学生原答案与红笔字母对比），或多标记联合证据。

**FN（3 个）**: Q11/Q22/Q25。VL 逐次检测的标记数量波动（P1 每次 9-10 个、P2 每次 7-10 个），部分题的标记没被 VL 报出来或 position 文本没提题号。

**题型 13.8% 的真相**: 分类学口径冲突，不是识别错误。GT 用教学口径（阅读理解/完形填空），scanner 用形式口径（choice/cloze/grammar_fill）。同一份卷子：Q1-15 教学上是"阅读理解"，形式上是"语篇填空"（scan=cloze）；Q25-30 教学上是"完形填空"，形式上是"无选项填词"（scan=grammar_fill）。**需要产品决策**：错题本按哪个口径展示？建议 scanner 输出双字段（sectionName 教学口径 + questionType 形式口径）。
