# gaozhong.online — 产品差距分析与改进路线图

> 版本: 1.0 (2026-08-17)
> 视角: AI 学习支持（不是技术视角）
> 依据: 2026-08-16/17 七轮实测（英语澜大训练1，人工核验 GT）+ 全链路代码考察
> 产品定位回顾: 上传已批改试卷 → AI 识别错题 → 分科错题本 + 薄弱知识点分析。**不做批改，做"错题价值挖掘"**

---

## 1. 用户学习闭环现状总览

一个学生用户的完整旅程：**上传 → 等待 → 确认/复核 → 看错题 → 学习（解析/知识点）→ 复习（重做/自测）→ 追踪改善**

| 环节 | 现状 | 评分 | 关键证据 |
|------|------|:---:|------|
| 上传 | 多页上传+自动排序 | 🟢 85 | 文件名页码排序已实现 |
| 题目识别 | 100% 召回/100% 精确 | 🟢 95 | 7 轮实测稳定，含跨档题号 |
| 错题判定 | P83.3% / R87.0% / F1=85.1% | 🟡 60 | 误判 4 + 漏判 3（29 题 23 错） |
| 复核确认 | 架构齐全（review_status/PaperReview） | 🟡 65 | 效率未优化，漏判题无提示 |
| **错题内容** | **严重残缺** | 🔴 30 | 见 §2 — 最紧急 |
| 知识点归因 | 有但泛化 | 🟡 50 | 输入残缺导致输出空洞 |
| 复习/重做 | **不存在** | 🔴 0 | 错题本是静态列表 |
| 薄弱点追踪 | 只有当前快照 | 🟡 40 | 无时间维度、无掌握度 |

**核心判断：识别能力已跨过可用门槛（F1=85%），但错题本内容质量和学习闭环的缺失，让 85% 的识别精度无法转化为学习价值。**

## 2. 差距详析（按对学习价值的影响排序）

### 差距 1：错题内容残缺 — 学生打开错题本，一半题目没法用 🔴 P0

实测发现四个内容断层：

| # | 问题 | 代码证据 | 对学生的影响 |
|---|------|------|------|
| 1a | **阅读理解文章全部丢失** | `parse_by_batches` 返回 `'passages': []`（batch 路径根本不提取 passage） | 阅读错题只剩题干和选项，没有文章根本无法复习 |
| 1b | **题干截断 300 字符** | `llm_parser.py` `questionText[:300]` | 完形/语篇填空的句子被切断，题目不可读 |
| 1c | **学生答案和正确答案全空** | `api-server.js` 适配层硬编码 `studentAnswer: '', correctAnswer: ''` | DeepSeek 拿着"学生答案: 未知"分析，解析只能泛泛而谈 |
| 1d | **错题卡片无题目截图** | bbox 已可靠（本次修复后）但未生成裁剪图 | 学生看到的是残缺 OCR 文字，不是原题 |

**讽刺的是：答案就在卷子上。** 这批试卷的教师批改风格是每题旁写正确答案字母（红笔）——正确答案是可以直接读出来的；学生手写答案 TextIn 手写区域也能覆盖。这是"捡现成"的改进。

### 差距 2：判错差最后一公里 — 83% 精确率不足以让用户信任 🟡 P1

- 4 个误判全是同一类：**教师每题都写红笔字母（含对的题）**，形态学（红笔位置/能量/类型）无法区分"字母=对"还是"字母=错"
- 3 个漏判源于 VL 标记→题目匹配用"题号N旁边"文本描述（有损）
- 复核界面存在但没有**置信度分层**：21 道判定错题让用户逐题确认，每题 30 秒 = 10 分钟，用户会直接放弃复核 → 产品承诺的"复核后 100%"落空

### 差距 3：学习闭环断裂 — 错题本只有"存"，没有"学" 🔴 P1.5

- 无重做模式、无间隔复习、无掌握度状态
- 错题本 = 相册，不是学习工具。艾宾浩斯遗忘曲线完全没利用
- 学生的真实需求："考前把这两周的错题再过一遍/再做一遍" — 目前无法支持

### 差距 4：知识点诊断深度不足 🟡 P2

- KnowledgeMap 只统计"某知识点错 N 次"（快照）
- 没有：同知识点跨试卷错误率趋势（在变好还是变坏）、具体混淆点（"which/that 混用"而非"考察定语从句"）、掌握消化状态

### 差距 0（前置）：10 项修复未部署 ⚠️ 立即

生产环境 VL 通道从未工作过（http→301）、imgToBase64 data-URL、页码分发、bbox 兜底等 10 项修复只在本地。**不部署，线上用户用的还是残血流水线。**

## 3. 改进路线图

### 阶段 0：部署现有修复（本周，0 开发量）
```
bash deploy.sh → 线上跑一份澜大训练1 → 对比本地成绩确认
```

### 阶段 1：错题内容完整性 — "让错题本能看"（1-2 周）

| # | 任务 | 要点 | 预期效果 |
|---|------|------|------|
| 1a | passage 穿透 | batch prompt 增加 passages 字段（section prompt 已有先例），`_llm_result_to_gaozhong` 透传 | 阅读题带全文 |
| 1b | 题干不截断 | `[:300]` → 完整存储（截断移到展示层） | 完形/语篇题完整 |
| 1c | **答案提取** | 新增 VL 步骤：裁剪图读学生手写答案 + 红笔字母（正确答案）。教师"每题写字母"的风格反而是稳定的答案源 | studentAnswer/correctAnswer 填充 → DeepSeek 输入完整 |
| 1d | 题目截图 | 用已有 bbox + ImageMagick（thumbs 已在用）生成 `p{page}_q{num}.jpg`，错题卡片以图为主、OCR 文字为辅 | 错题卡片视觉还原 |

**验收**: 任选一份试卷，错题本里每道题 = 原题截图 + 完整题干 + 文章 + 学生答案 + 正确答案

### 阶段 2：判错冲刺 95% + 复核提效 — "让用户敢信"（2-3 周）

| # | 任务 | 要点 |
|---|------|------|
| 2a | VL 输出坐标 | 分类 prompt 要求输出标记网格坐标（如 `{"row": 12, "col": 3}` 或归一化 xy），几何匹配替代"题号N旁边"文本匹配 |
| 2b | **语义比对判错** | 学生答案 ≠ 红笔字母 → 错；相同 → 对。直接消灭 Q6/Q10/Q24/Q66 这类误判（占当前 FP 的 100%） |
| 2c | 复核红绿灯 | 绿=高置信自动通过；黄=需确认（一屏：原图裁剪 vs 判定）；红=证据冲突。复核从"逐题校对"变"只看黄灯" |
| 2d | 漏检提示 | 页级提示"第 2 页有 3 题未检测到批改痕迹"，给 FN 兜底入口 |

**验收**: 澜大训练1 上 F1 ≥ 92%，复核操作 ≤ 10 次点击

### 阶段 3：学习闭环 — "让错题活起来"（3-4 周）

| # | 任务 | 要点 |
|---|------|------|
| 3a | 重做模式 | 题目截图卡片 → 遮住答案 → 学生作答（手写拍照或选择）→ 自动比对 → 掌握标记 |
| 3b | 间隔复习 | SM-2 简化版：错题按 1/3/7/14 天重现，答对延长间隔，答错重置 |
| 3c | 掌握度状态机 | 未掌握 → 学习中 → 已掌握（连续 2 次答对）；KnowledgeMap 只显示未消化部分 |
| 3d | 错题组卷 | 按知识点/时间筛选错题 → 导出可打印重做卷（PDF） |

**验收**: 学生每周打开 ≥ 2 次，两周后旧错题有掌握度记录

### 阶段 4：诊断深化 — "从错题本到学习顾问"（之后）

- 知识点趋势线（跨试卷错误率变化）
- 具体混淆点归因（有完整答案后 DeepSeek 可输出"你把 X 误用为 Y"）
- 学习周报（学生/家长视角：本周新增错题、消化数、薄弱点变化、建议）

### 横切：多科目扩展

11 阶段解析 + LLM prompt 目前仅英语。语文/数学需要独立题型正则与 prompt（REQUIREMENTS 已列为已知短板）。建议在阶段 1-2 完成后启动（复用全部管线，只换解析层）。

## 4. 度量体系（延续量化驱动）

- **回归基准**: 每次改动跑 `eval/run-paper.mjs` + 澜大训练1 GT（已建）
- **扩展基准**: 用户每提供一份"题目及错题情况"就新增一份 verified GT（目标 10 份）
- **产品指标**（新增，需埋点）: 复核完成率、错题本周活跃、重做完成率、7 日掌握率
- **当前技术基线**: 题目 100/100，判错 P83.3/R87.0/F1=85.1，页码 96.6%

---

## 5. 一句话总结

**识别流水线已经毕业（85%），现在要毕业的是产品：先把错题本里每道题变完整（阶段 1，大部分是捡现成），再把判错推过信任线（阶段 2，语义比对是钥匙），然后让错题被反复使用而不是躺着（阶段 3，间隔复习是灵魂）。**
